Lost & Found Game Plan

We build a website for mall security. A guard types "lost boy, about 6, red t-shirt", and it answers three questions from the mall's camera recordings. To prove it works in general and not by luck, we build it on Case A and then test it once, blind, on Case B, a different family and story in the same mall. Each case also hides a trick clip the system must not fall for.

1 · Where did the family go?

Their path from camera to camera.

2 · Where did they lose the child?

The exact clip and second.

3 · Where is the child now?

The last camera that saw them.

How to use Kling 3.0 for this

Rules the prompts follow

  • Order: scene → characters → action → camera → audio. This is the order most Kling 3.0 guides recommend.
  • Action in time steps (0–4 s, 4–9 s …) so the important moment happens on time and inside the 15 seconds.
  • One camera instruction only: "locked-off static shot". Never mix in pan or zoom words.
  • Plain, concrete words, no "4K masterpiece" filler. Each prompt is about 1,500–2,200 characters; Kling's limit is 2,500.
  • Lookalikes in the background (other thobes and abayas) on purpose: real malls have them, and the system must cope.

Settings in Higgsfield

  • Model Kling 3.0, aspect ratio 16:9, duration 15 s.
  • Elements (best): create one Element per character from its 2–3 pictures below, named with the tag shown (e.g. @BoyA). Use the "with Elements" prompt version.
  • No Elements? Use the "full description" version, and if possible give the character picture as the start or reference image.

  • Redo a clip if the camera moves, a character's clothes change colour, or the key moment doesn't happen.

Prompt version:

Budget: exactly 15 video credits

Where they go

  • 12 core clips: A1–A6 and B1–B6. Every one is needed for the tests.
  • 3 spares to redo clips that come out wrong (wrong clothes, moving camera, key moment missing). This happens often with AI video.
  • Spares left over at the end: A7, then A8 (extras for the demo video).

Order

  1. Character pictures + Elements (images, not video credits).
  2. A1 + A3, then stop: we test them in CreativAI first.
  3. A2, A4, A5, A6.
  4. B1–B6, into demo/raw/case-B/, sealed.
  5. Spares: redo failures, then A7, A8.

Accept a clip only if

  • the camera never moves;
  • the clothes keep the same colours and match the character pictures;
  • the key moment really happens (A3: the boy leaves the store; A6: the boy never leaves the table);
  • there is no text, logo or watermark in the picture.

How we know it works

The blind-test rule

  1. Build and adjust everything on Case A only.
  2. Case B stays sealed: nothing is run on it.
  3. When Case A passes, the code is frozen (tag freeze-v1).
  4. Case B runs once, and the result is published as it comes out, pass or fail.

Train on one set, test once on a set you never touched. That is what makes "it works in general" a fair claim.
