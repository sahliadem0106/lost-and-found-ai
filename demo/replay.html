Behind the replay

How it was built

The whole project, end to end: how the footage was made, how CreativAI was used, what each script does, what works, its limits and their fixes, what a real deployment would cost, and why this field excites me.

The pipeline

1 · Footage

Make the cameras' video

No real lost-child footage exists, so the story was staged with AI video. Each character got a reference sheet (Qwen Image 3); Kling O3 then generated 15-second CCTV clips from a prompt plus the sheets, so the same family appears in every camera.

2 · Indexing

Give the footage to CreativAI

Each clip is uploaded to a CreativAI collection, tagged with its camera and start time, and indexed (cut into 16-second chunks CreativAI can search and reason about).

3 · The agent

Map + Eyes, in a loop

From the guard's description, the agent asks the camera map where the family could be, asks CreativAI about only that footage, and repeats until it has the separation point and the boy's current location.

4 · Showing it

Replay and console

The agent records every step, prompt and answer. This page replays that record; a local console lets a guard type a report and watch the agent run live.

The tools

Video intelligenceCreativAI

The Eyes. Collections and chunk indexing store the footage with camera/time tags. Data plates + knowledge extraction answer plain-English questions per clip (is the family here, is the child alone, when does he walk away). Search was tested too, but it can't time events inside a clip.

Generation APIHiggsfield

One API for all the image and video models used to stage the footage, with a free price check before every paid request.

Image modelQwen Image 3

Made the seven character reference sheets (front, side and back of each person). About $0.04 each.

Video modelsKling O3 · Kling 3.0

Kling O3 image-reference turned prompts + character sheets into the clips (≈$1.07 per 15 s). The two trick clips with strangers used plain Kling 3.0 text-to-video (≈$0.63).

RuntimeNode.js

Everything else is plain Node, with no packages: the camera map, the CreativAI client, the agent and the local server.

Checkingffmpeg · headless browser

ffmpeg pulled frames to check what each clip really shows and made light web copies; a headless browser tested this page step by step.

The scripts

FileWhat it doesDetails
mall_topology.jsonThe mall12 cameras with positions and placement, the walkways between them in metres, walking speeds, and the staged story's true timeline.
pipeline/graph.jsThe MapFrom a sighting at camera X and time t, lists the cameras reachable within 1–4 walkway hops and the time window for each (distance ÷ max and min walking speed, plus time in shops). Also checks whether a move is physically possible.
pipeline/creativai.jsAPI clientSmall REST client for CreativAI with retries; reads the key from the environment and never prints it.
pipeline/ingest.jsUpload & indexUploads a case's clips, tags them camera:<id> and clip:<id> with start-time metadata, waits for preprocessing, prices the indexing and runs it. Resumable.
pipeline/eyes.jsThe EyesBuilds a data plate from only the clips the Map picked, adds the three questions as knowledge-extraction columns, reads the answers back and caches them per clip, so reruns are free and instant.
pipeline/find-child.jsThe agentEntry at the doors → follow the family in time order → separation → follow the child (alone sightings only) → alert. Saves the result and a full trace of every step for this replay.
pipeline/replace-clip.jsSwap a clipRemoves a clip's old version from CreativAI and forgets its cached answers, so only the new version is asked about again.
pipeline/search.jsRaw searchRuns a CreativAI search with optional camera filters. Used in the first tests; kept for exploring.
server.js · case.htmlCase consoleLocal page where a guard types the report; the server runs the agent and streams its log live, then the page draws the result.
replay.htmlThis pageReads the agent's trace and animates it: every map state is plain data, and the map glides between states in either direction.

What works

Right answer, start to finish

Family's path, the moment the boy walked away, his route, and where he is now all match the staged story. The separation time is within 6 seconds.

The trap didn't work

A lookalike family (same thobe, same shemagh, a boy in red) sat two cameras away. The agent ruled it out because that boy wasn't alone.

From one description

No photo, no face recognition, no names: just what the parents told the guard. That's also kinder to privacy.

Looks only where it must

From each sighting the map allows a handful of cameras and minutes; everything else is never sent to CreativAI. That's what keeps a case fast and cheap.

Every step is explainable

Each decision comes with the exact prompt, CreativAI's word-for-word answer and the walking distance that makes it possible. A guard can check why.

Cheap to build and to rerun

About 96 CreativAI credits for the whole project. Answers are cached, so replaying a case costs nothing and takes under a second.

Works for any building

The mall is one JSON file of cameras and walkways. Swap it for an airport, a stadium or a hospital, and the same code runs.

Fixable in one place

When two clips came back wrong, one script swapped them in CreativAI and only those two were re-asked. Every answer is now correct.

Limits, and how to fix each one

LimitTested on one staged case

The rules were tuned on case A; the blind test on case B was never run.

FixRun the blind test, then build a test set

Case B's clips already exist (≈40 credits to run). Ten more staged cases cost about $70 in clips.

LimitAI video drifts from its script

A3 was scripted for the boy to leave at 9–13 s; he leaves at 4 s. Two clips had to be remade.

FixReal multi-camera footage

Public datasets such as MEVA, then a pilot with a mall (with consent and signage). Every clip here was also checked frame by frame before use.

LimitAll-or-nothing descriptions

On A3, CreativAI said "no. The man in the video is not carrying a shopping bag", while the parents were in the shot.

FixScore each detail separately

Ask about thobe, shemagh, abaya, bag one by one and match on most of them, not all.

LimitAmbiguous scenes can fool the Eyes

The first atrium clip had two boys in red; CreativAI matched the wrong one.

FixA second opinion

Re-ask when answers conflict, add a person detector / re-identification model as a cross-check, and let a guard confirm before an alert goes out.

LimitTiming from a single answer

The separation second ("4") isn't verified frame by frame.

FixZoom in on the key moment

Re-ask about the few seconds around it, using a shorter clip cut at that point.

LimitSearch can't rank or time events

For "boy alone", every clip scored 0.030–0.033.

FixAlready fixed: questions, not search

The Eyes use data plates and per-clip questions; search is kept only for exploring.

LimitFixed rules, no reasoning model

It can't adapt if the child changes clothes, the family splits up, or the mall has several floors.

FixAn LLM driving the loop

A model such as Claude could rephrase questions and handle unusual cases, for a few cents per case. Multi-floor is just more edges in the map.

LimitAbout 3 minutes to a first answer

Each question round takes about a minute.

FixIndex ahead, ask in parallel

Index the report window the moment the report starts, ask about several cameras at once, and use CreativAI live streams for instant footage.

What a real deployment costs

No need to index the whole mall all day. The parents' report gives a time window (here, arrival around 14:00 and the report at 14:27), so only that window is indexed, and only on the cameras the map says are reachable. Costs below use this project's measured rates.

PlanA paid CreativAI plan

Adds multimodal indexing (search with a photo of the parent) and live-stream sessions (RTSP), so footage is ready the moment a report comes in.

DataReal footage and a test set

MEVA or a mall pilot for real CCTV; about $70 for ten more staged cases.

ComputeOptional second pair of eyes

A detector + re-identification model on a GPU or edge box, to cross-check CreativAI on hard scenes.

Next steps, in order

  1. Run the blind test on case B and publish the result, pass or fail.
  2. Score descriptions detail by detail instead of one all-or-nothing question.
  3. On-demand indexing of the report window, plus parallel questions.
  4. Guard confirmation before an alert is sent, and a re-check of the key moment.
  5. Real multi-camera footage (MEVA), then a live-stream pilot.
Why this field excites me

I didn't build a vision model here: I connected tools and built the logic around them. And every tool opened a new question for me. When a video AI like CreativAI answers confidently and is wrong, how could it know it isn't sure? How little footage do you really need to look at, and how cheaply and quickly can it be done? Can knowing the space, like a camera map, make video AI more reliable?

That's what draws me to computer vision: not just getting an answer, but making it accurate, efficient and useful in the real world. It's what I want to keep exploring.

Run it yourself

Node.js 18+, nothing to install. The cached answers mean no API key is needed to replay case A.

git clone https://github.com/sahliadem0106/lost-and-found-ai.git
cd lost-and-found-ai
npm run find:a     # the agent's full log in the terminal
npm start          # then open http://localhost:3000/replay.html

Limits: the footage is AI-generated, the rules were tuned on this one case, and the blind test on a second case was not run. Full write-up and tutorial in the README.

Footage is AI-generated for this demo (Kling via the Higgsfield API) and the story was staged; the agent's run and CreativAI's answers are real and are stored in CreativAI's data plates for this collection. Code, tutorial and honest limits: github.com/sahliadem0106/lost-and-found-ai.
